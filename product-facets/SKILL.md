# 产品多面（product-facets）

## Overview

一个应用产品是若干正交「面」（facet）的并集，不是「一个能跑的功能」。给定一个项目的基调，本 skill 推导出一张「面地图」——它该有哪些面、每面多深、每面怎么验——并逐面独立设计 / 落地 / 校验。目的：防止功能面能跑、责任 / 安全 / 发布面全裸奔，同时留自用→商用的升级窗口。

核心机制是一条三轴推导函数：`面地图 = f(交付意图, 业务性质, 质量强度)`。f 是「提示器 + 判定器」——产出候选面 + 风险提示，最终激活 / 深度由开发者逐面拍板。

## Resource Guide

- `references/axis-enumeration.md` —— 三轴的枚举与拆法，采基调前必读。
- `references/side-catalog.md` —— 基础面 + 条件面的目录与风险 FLAG，推导候选面时查。
- `references/per-side-protocols.md` —— 每面的设计 / 落地 / 校验协议，逐面拍板后查。
- `examples/worked-example.md` —— 一个完整推导示例（conver），首次使用前读。

## Workflow

1. **采三轴基调** —— 按 `axis-enumeration.md` 收集：交付意图（受众 × 商业化）、业务性质（外部关系扫描）、质量强度（规模 × 关键性 × 生命周期）。基调缺项时，列出缺失项让开发者补，或显式标「假设」再继续推导，不得静默脑补。
2. **推导面集合** —— 基础面（功能/责任/安全/发布）恒在；按 `side-catalog.md` 由 f 拉入条件面。
3. **逐面生成** —— 每面落出：定义 + 风险提示 + 协议引用。
4. **标质量硬约束** —— 引用 ISO 25010 词表，逐条标硬 / 软。
5. **逐面拍板** —— 对每面显式判定「激活/关闭 + 深度」，对每质量属性判定「硬/软」。
6. **输出面地图** —— 见 Output Protocol。
7. **路由执行** —— 执行与校验交给 project-kickoff / tdd / code-review 等，本 skill 不替它们跑流程。

## Output Protocol

**面地图**（每面一行）：

| 面 | 激活/关闭 | 深度 | 风险点 | 协议引用 | 执行路由 |

**质量硬约束清单**：ISO 25010 词表条目，逐条标硬 / 软。

**升级窗口标记**：当前档关掉的面 + 升到下一档要打开的面 + 触发条件。

## Boundaries

- 推导不替拍板：f 产出候选面与风险提示，激活 / 深度由开发者判定。
- 不 OWN 执行与校验：路由给现有 skill，不重写 project-kickoff / tdd / code-review。
- 质量属性不深入测量：词汇引用 ISO 25010、机制借鉴 ATAM，不重造质量模型。
- 不适用：一次性脚本（无需分面）、已有完整方法论且不愿变更的项目。

## Quality Standard

- 每面落到「激活/关闭 + 深度」的显式判定，无「这个项目可能要考虑 X」这类无落点话。
- 责任 / 安全 / 发布作为一等面被显式检查，不被「功能能跑」遮蔽。
- 面地图对给定基调自洽，可对照 `examples/worked-example.md`。
- 质量硬约束清单引用 ISO 25010 词表且逐条标硬 / 软。
