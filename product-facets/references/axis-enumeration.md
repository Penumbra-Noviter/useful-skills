# 三轴枚举

推导函数的三个输入轴。采基调时逐轴填写；每轴用「问题 + 正交子维」组织，便于扩展，不是封闭清单。

## 轴 A · 交付意图

回答「给谁用、怎么商业化」。两个正交子维：

- **受众**：只有我 / 内部团队 / 公众
- **商业化**：免费自用 / 免费分享 / 开源 / 售卖（交付给具体客户）/ 售卖（公开兜售）

组合成常见档（谱系，非二元开关）：自用 → 自用+分享 → 内部团队 → 商用交付 → 商用兜售 → 开源。

易漏的两档：**开源**（激活许可证选择、供应链安全、社区维护、文档，与商用几乎完全不同）与**内部团队**（内部分发、多用户/共享态、内部策略）。

## 轴 B · 业务性质 / 风险面

回答「产品碰哪些外部实体」。枚举原则 = 产品与外部实体的关系，按关系类型扫描：

| 外部关系 | 含义 | 典型风险 |
|---|---|---|
| 逆向来源 | 由他人产品逆向自建 | 实质相似审查 / 清洁室 |
| 平台对抗 | 自动化操作某平台 | ToS 禁止 / 法律灰区 |
| 数据类型 | 采集/处理用户或第三方数据 | 个保法 / 隐私 |
| 第三方 IP | 触碰他人版权/商标 | 版权 / 授权 |
| 纯本地 | 无上述外部关系 | 风险最低 |

扫描时一并查的已知缺漏（勿因不在表内而漏）：金融/支付（PCI-DSS、反洗钱）、人身安全（safety，医疗/工控）、未成年人保护、供应链（第三方依赖投毒）。

## 轴 C · 质量 / 非功能强度

回答「做到多好」。驱动 = 规模 × 关键性 × 生命周期：

- **规模**：单用户 / 小团队 / 大规模并发
- **关键性**：玩具 / 一般工具 / 安全攸关（医疗·金融·工控）
- **生命周期**：一次性 / 短命 / 长期维护产品

**资源约束**（solo 开发、时间/人力预算）显式排除——它是约束不是需求，不参与质量推导。

输出侧的质量属性词汇引用 ISO 25010:2023 的 9 特性（功能适用性、性能效率、兼容性、交互能力、可靠性、安全性、可维护性、灵活性、safety），不自己造词。
