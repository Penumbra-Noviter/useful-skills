# 语言负面清单（Do-not-report）

面向 Standards / Falsify 轴子的语言特定「不该报」排除清单。在 code-review skill 的
Report credibility gate 的通用假阳性跳过清单**之上**叠加：命中排除项时，除非 diff
给出具体反证（证明该排除不适用），否则不得上报。

**读取契约**：由编排者按 diff 语言解析出对应节，随子代理 brief 一并下发。当前覆盖
Python / TS·JS / Go 三节。意图与结构提炼自 alibaba/open-code-review 的
`internal/config/rules/rule_docs/`（Apache-2.0），按本项目口径精简——它是一部
「检查表 + 排除表」，剔除排除表后失去 precision 保护，本文件只保留排除表这半边。

**维护约定（防双源漂移）**：每条排除的阳性检项本体在 OCR 规则文档（外部上游），
本文件是面向本项目子代理的精简副本；新增语言节时对照上游 `rule_docs/<lang>.md`
提炼。上游更新优先，本文件按需对齐，不逐字同步。

## Python

> 总原则：只报确有可能是真实缺陷的项。正确处理、可辩护的取舍、上游已验证的边界
> 一律不报——报错的信任成本高于漏掉的次要问题。

- **可变默认参数 / 共享状态**：`def f(x=[])`、类级可变属性跨实例共享、闭包捕获循环变量。
  **不报**：函数从不修改该参数；共享默认值是刻意的、有注释的缓存或哨兵。
- **边界与极端输入**：假设非空的空输入（`xs[0]`、`max()`/`min()` 未先处理空集合）、
  off-by-one、`None` 抵达假定有值的代码、浮点 `==` 比较、`//` 意外截断、除零、
  `d[k]` 未处理缺失键。
  **不报**：调用方或类型契约已排除的边界；上游已验证的输入不会到达的路径
  （先 `file_read` 确认数据源再报）。
- **异常处理**：裸 `except:`、过宽的 `except Exception`、静默 `pass` 丢弃异常、
  `raise` 丢失原 traceback、覆盖过多代码的宽 `try`、用 `assert` 做运行时输入校验。
  **不报**：`except` 捕捉的类型与守卫调用实际抛出的匹配且窄化有意义；`assert` 校验
  的是绝不会为假的不变量而不是外部输入。
- **身份与相等比较**：用 `is`/`is not` 比较字面量（字符串、数字、元组）、用 `==`
  比较 `True`/`False`。
  **不报**：`is` 用于单例/哨兵身份比较；`== None` 这类比较只是风格偏好——降级为
  minor，不阻断。
- **资源管理**：文件/套接字/锁/连接未用 `with`。
  **不报**：短命脚本；句柄已被外层 `with` 或框架生命周期管理（`file_read` 确认
  外围作用域再报）。
- **性能**：循环里 `+=` 拼字符串、list 重复成员测试（应为 set）、表达式循环内重算、
  `logging.info(f"...")` 提前格式化。
  **不报**：先确认数据规模和代码确实在热路径上；非热路径的性能"问题"不报。
- **并发与异步**：仅当有确凿的多线程/多进程/异步调用证据才报——GIL 下 threading
  做 CPU 活、check-then-act 竞态、`async def` 内阻塞调用、`asyncio` 任务创建不 await。
  **不报**：局部变量、共享数据的只读访问、无并发使用证据的代码（先确认调用上下文）。
- **安全敏感代码**：`eval`/`exec`/`compile` 于不可信输入、`shell=True` 拼接、
  `pickle`/`yaml.load` 反序列化不可信数据、SQL 字符串拼接、密钥入日志、
  `random` 用于安全令牌、未验证的文件路径拼接。
  **不报**：先验证数据源——输入实际是可信常量而非攻击者可控（确认后再报）。

## TypeScript / JavaScript

> 总原则：prefer precision over recall；只报确有可能是真实缺陷的项。框架已处理、
> 工具链已强制、学术界无共识的风格问题一律不报。

- **死代码**：永不可达的分支、声明未读的变量/导入、无保留意图的大段注释代码。
  **不报**：`.d.ts` 等声明文件中的未使用导入（声明即接口，不执行）。
- **相等与类型**：`==`/`!=`、`any` 泛滥、解构/取值前缺 null 检查。
  **不报**：`===` 由 linter/编译目标强制、类型守卫已收窄的路径、有注释说明理由的
  必要 `any`（如逐步迁移期）。
- **React 最佳实践**：Hooks 规则违反（顶层调用、仅 React 函数内调用）、渲染期间副作用
  （API 调用、DOM 操作）、组件内声明组件。
  **不报**：`useMemo`/`useCallback`/`React.memo` 的过度优化——未证实性能瓶颈的
  记忆化建议是噪音，不报；`React Compiler` 已在处理的场景不报。
- **异步处理**：async 函数缺错误处理、回调地狱、循环内该并行却串行。
  **不报**：错误路径已被框架错误边界/顶层 catch 覆盖；有依赖关系的操作串行是
  正确选择。
- **安全**：`innerHTML` 直插用户输入、`eval`/`Function`/字符串 `setTimeout`、
  `document.write()`、密钥泄露、篡改原生原型。
  **不报**：`innerHTML` 插入的是常量 HTML（非用户输入）；`eval` 出现在显式代码加载
  插件面；框架默认已转义（React JSX 转义等）且未被 `dangerouslySetInnerHTML` 破坏。
- **潜在缺陷但边界存疑**：`parseInt` 缺 radix、`Array.isArray` 对泛型不做判断、
  `Object.keys` 顺序假设、getter 内副作用。
  **不报**：调用方传入的值已限定类型、行为依赖版本已固定、或属于 TypeScript
  类型系统/运行时可辩护取舍。

## Go

> 总原则（上游原文精神）：只报变更代码及其可达上下文里可能真实的缺陷。正确性/安全
> 发现视为阻断，纯风格建议非阻断。跳过 `gofmt`/`go vet`/Staticcheck/编译器已可靠
> 确定的内容——除非 diff 表现了这些工具不会表达的具体用户可见后果。

- **错误、panic 与 API 契约**：忽略/覆盖返回值错误、`fmt.Errorf("...: %v", err)` 丢失
  原 cause（需要 `errors.Is`/`As` 时）、请求/工作路径上不该 panic 的 `panic`/
  `log.Fatal`/`os.Exit`、defer 清理覆盖主错误。
  **不报**：明确的 best-effort 操作且忽略失败是安全/文档化的；不可能的内部不变量或
  文档化的程序员契约；`%v` 封装足够且无人需 `errors.Is`。
- **nil、接口与值语义**：typed nil 装入非 nil 接口后被当缺席、nil map 写入、
  nil 通道阻塞、含 `sync.Mutex` 的结构体用值接收者拷贝后首用、值拷贝静默变体、
  `sync.Once` 用于必须重试的工作。
  **不报**：刻意的不可变值对象；所有权/生命周期无歧义；`Once` 语义本就如此且无重试
  需求（报前确认该次失败是否会阻塞后续正确性）。
- **context 与 goroutine 生命周期**：请求域工作用 `context.Background()`/`TODO()`、
  context 存结构体、`WithCancel` 的 cancel 不调用、请求路径缺取消的阻塞 I/O、
  goroutine 长于 owner 存活、go 1.22 前循环变量捕获语义问题。
  **不报**：独立的后台工作；外部必须接口固定签名的 context 存结构体；所有权转移与
  最终取消清晰可见；闭包观察的是每次迭代新变量（按 module 的 go 指令判断语义）。
- **通道、锁与共享状态**：无同步的并发读写、互斥锁跨越阻塞 I/O、`RLock` 中改数据、
  可能无限阻塞的收发、多 closers、`select` default 空转、WaitGroup `Add` 与 `Wait`
  竞态。
  **不报**：无可达并发证据（先看调用点）；不可变数据、goroutine 局部数据、所有权
  保证同步；已证成对的同步握手。
- **定时器与资源生命周期**：timer/ticker 遗留运行、`time.After` 于重复循环、
  跨 Go 版本的 timer `Reset`/`Stop` 假设、closable 资源未全路径关闭、defer 在可长
  循环内、`sql.Rows` 缺 `rows.Err()`。
  **不报**：缺失 `Stop` 单作为 GC 泄漏——Go 1.23+ 可回收未引用 timer/ticker，
  老版本语义不同；资源已交给负责关闭的调用方/框架；小且静态有界的循环。
- **集合、切片与数值边界**：返回/缓存被复用的后备存储、append 别名共享后备数组、
  越界索引/长度算术、整数窄化/溢出/符号比较、变号负数转 huge size。
  **不报**：所有权已确认、zero-copy API 是刻意的；架构相关的 `int` 宽度已在
  目标架构上辩护。
- **安全敏感边界**：SQL/shell/URL/路径/模板/正则从不可信输入拼接、路径穿越、
  `text/template` 替换 `html/template`、SSRF/凭据泄漏、`math/rand` 用于安全令牌、
  `reflect`/`unsafe`/cgo 无窄不变量。
  **不报**：先确认攻击者可控或信任边界——输入是可信常量而非用户可控则不报安全类；
  `text/template` 用于非 HTML 输出默认不报；模拟/采样/负载均衡/测试中 `math/rand`
  不报；普通 reflection（非 unsafe 指针/layout 假设）不报。
- **测试与评审范围**：默认评审生产 Go 变更；`*_test.go` 由编排器的 manifest 排除。
  **不报**：`gofmt`/`go vet`/Staticcheck/linters/编译器已强制的事项（格式、导入序、
  命名偏好、简化）绝不作为阻断发现；不要求基于时序的 flaky 竞态测试——只对
  具体的正确性/并发/错误/边界失败模式建议确定性测试。

### 上游与冗余策略

上游每个 `.md` 都是「阳性检项 + Do-not-report 排除」成对出现；本文件只收了排除
半边，检项半边由 sub-agent 自身的能力承担（它有 repo 上下文与工具）。若你发现某
语言遗漏了高频误报类型，先查上游 `rule_docs/<lang>.md` 是否有对应排除，有则提炼，
无则按本项目经验补一条并标注「项目经验」来源。
