# Falsify 与审计产出消费坑

从个人知识库 `demo/经验/` 蒸馏的审查期坑。Falsify 轴构造证伪输入、以及消费审计产出时先读；每条给「反模式 → 正解 → 验证点」，来源见知识库同名笔记。

**维护约定（防双源漂移）**：经验本体在知识库 `demo/经验/`，本文件是面向子智能体的缓存副本，知识库为唯一权威。每次 `distill-lesson` 蒸馏新审查坑后顺带核对本文件；冲突时以知识库为准重写。

- **Falsify 钉住缺陷所在层**：对迭代类系统（演化、重试、多轮聚合）先定位缺陷层，测试用最小步数（`generations=1` / `rounds=1`）钉住该层，不用端到端默认参数——多代迭代会把单层缺陷掩盖。判断标准：删掉修复后哪个测试会红。（`Falsify测试要钉住缺陷所在层`）
- **回归测试先红是硬验收**：按症状描述写的回归测试可能恒绿。写完后在旧实现上跑一次确认红；红不起来说明没锁住真实触发路径，要解剖缺陷机制找无互斥/无免疫的路径，不硬改断言凑红。（`回归测试须锁定真实缺陷路径`）
- **Falsify 覆盖防御机制自身状态机**：有序占位符/序号/id 分配器不能只测单实例输出正确，必测多实例交错 + 用户内容占用中间序号，断言「每项恰出现一次、无泄漏」。（`占位符计数器失同步——Falsify 须覆盖防御机制自身状态机`）
- **覆盖率数字带口径**：审查/汇报覆盖率必须附 `--cov` 范围（生产模块清单或全库、是否含 tests）。不带口径的数字跨会话不可复现，无法裁决。（`覆盖率数字必须带口径声明`）
- **审计产出是时间快照**：执行 CR/技术债工单前先 `git grep` 复核当前代码，已就绪项标「复核确认」不盲目重改；票面修复建议是候选假设，先读代码验证方案成立再动手。（`审计快照过期需复核` / `技术债票面修复建议须实证复核`）
