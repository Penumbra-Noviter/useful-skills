# kb-search：经验实时检索

## 定位

预检闸门之外，开发全程在问题发生时刻打捞经验：报错/调试时、写测试前，30 秒内从 `经验/` 原子笔记与共享记忆区定位与当前问题最相关的 ≤5 条。**检索只读**，不改动任何笔记。召回策略：**向量语义检索优先，grep 兜底链保障**——server 不可达或向量零命中时自动降级，用户无感知。

## 触发时机

- **报错 / 调试失败时**：必查。检索入口 = 报错文本（可直接作向量查询，另抽技术词备 grep 兜底）
- **写测试前**：必查。检索入口 = 测试场景描述（测试/夹具/mock/固定日期…）
- **重构 / 架构改动前**：随已有 ADR 流程顺带检索

## 工作流程

### 1. 解析输入

| 输入 | 必填 | 来源 |
|---|---|---|
| 报错文本 或 关键词列表 | 是 | 用户提供 / 当前错误 |
| 项目名 | 是 | 库路由查表确认注册表名 |
| 技术栈 | 否 | 当前项目（Tauri/Rust/FastAPI…） |

产出两样东西：**① 向量查询词**（改写后的自然问句，报错原文直接可用，不抽稀）；**② grep 兜底关键词**（从报错抽英文技术词 / 常量名优先——`is_dev`、`worktree`、`pyc`、`ctypes`…，再补 1-2 个场景词；纯中文报错直接用原文关键词）。

### 2. 库路由（定位 vault 与注册表项目名）

① 项目仓库 `KNOWLEDGE_BASE.md` 读所属 vault 与项目登记名 → ② 库级注册表（demo 为 `项目/README.md`）按项目名反查 → ③ 未登记 → 默认 demo vault、项目名原样检索，并提示补登记。经验目录为 `<vault>/经验/`。

### 3. 检索（git bash，默认 vault `D:/Desktop/knowledge base/demo`）

**① 向量检索（优先，主召回）——本地 hy-memory server**

```bash
KB="<vault 根路径>"    # 由库路由解析，默认 D:/Desktop/knowledge base/demo
QUERY="<向量查询词>"    # 改写后的问句，如：打包逆向遇到 pyc 反编译该怎么办

curl -s -m 8 -X POST http://127.0.0.1:19527/api/v1/search \
  -H "Content-Type: application/json" \
  -d "{\"query\":\"$QUERY\",\"user_id\":\"local\",\"include_sources\":[\"zcode\",\"kb\"],\"limit\":10,\"min_score\":0.4}" \
  -o /tmp/kb_search.json 2>/dev/null
```

判读（顺序判定，命中判定即止）：

- **server 不可达**：curl 退出码 ≠ 0（连接拒绝 = 7）或响应非 200 / 非 JSON → **整套跳 ② 兜底链**（不提示 server 故障，用户无感知）
- **向量零命中**：`memories.normal` 缺失或为空 → **跳 ② 兜底链**
- **有命中**：取 `memories.normal[]` 为候选集 A。逐条以 `meta[0].path` 还原源文件绝对路径（kb = vault 笔记，zcode = 记忆节点），**剔除路径含 `学习/` 的命中**（保留旧边界：不检索学习笔记），**按 `score` 降序排序**（注意：server 返回顺序不保证按 score，必须自行排序）

**② grep 兜底链（保障，三步完整保留）**

server 不可达 / 向量零命中时**完整执行**；向量有命中时，用 ①② 的关键词精确命中与 ③ project:通用 补充候选（与向量命中合并去重，向量优先）。

```bash
KW="<grep 兜底关键词>"  # 每词执行一遍，结果并集后按优先级排序

# ① 标题命中（优先）：文件名含检索词
ls "$KB/经验" | grep -i "$KW"

# ② 全文兜底：正文含检索词——纯中文标题笔记（45%）靠这步召回
grep -ril "$KW" "$KB/经验" --include="*.md"

# ③ project:通用 兜底：必并——方法论/跨项目经验在具体项目预检里会漏读
grep -rl '^project: 通用' "$KB/经验" --include="*.md"
```

### 4. 聚合与裁剪（合并去重）

- **去重键 = 归一化绝对路径**：统一正斜杠 + 转小写（Windows 大小写不敏感）；grep 的裸文件名先补 `$KB/经验/` 前缀再归一化
- **同路径只展示一次，向量命中优先**（向量与 grep 命中同一文件时，不重复展示）
- 排序：**向量命中（score 降序）> 标题命中 > 正文命中；项目内 > 通用；多检索词命中者优先**
- 裁 **Top 5**

### 5. 输出

每条一行（不打开正文），summary 必须来自文件 frontmatter 实际字段，**不得编造或改写**：

- vault 笔记读 `summary:`；zcode 记忆文件读 `description:`（zcode 无 summary 字段，description 为其等价摘要）；两字段都缺 → 如实标「无 summary」
- 提取命令：`awk '/^summary:/{sub(/^summary: /,""); print; exit}' "<文件>"`（zcode 文件把 `summary` 换成 `description`）

```text
[命中] <标题> | <summary> | <相对路径> | 命中词: <词1>, <词2>
```

- **相对路径**：kb 命中 → 相对 vault 根（`经验/xxx.md`）；zcode 命中 → 相对 `~/.zcode/cli/memories/projects/`（`<项目>/memory/xxx.md`）。绝对路径始终在手（向量 meta[0].path / grep 输出），精读直接可用
- **命中词**：向量命中 → `语义(score=<X.XX>)`；grep 命中 → 实际命中的关键词

### 6. 精读（按需）

只打开与当前问题直接相关的命中正文，**精读预算 ≤1000 字**；超出只带摘要。

### 7. 留痕

命中清单记项目 `DEV_LOG.md` 一行（召回轨迹，与预检同构）：读了哪几条、跳过哪些；若本阶段踩的坑库里其实有笔记但未命中 → 记**漏招**并优先补 keywords。

## 示例

报错 `打包逆向遇到 pyc 反编译该怎么办`，项目未登记 → 默认 demo vault：

1. 向量查询词 = 报错原文改写；grep 兜底关键词抽 `pyc`、`逆向`
2. 库路由：未登记 → 默认 vault `D:/Desktop/knowledge base/demo`
3. 向量检索（server 正常）→ 候选集 A 按 score 排序，首条命中 `Python 3.12 pyc 逆向用重编译对比闭环取代反编译器`（score 0.72，`meta[0].path` = vault 绝对路径）
4. grep 兜底并行：`ls|grep pyc` 标题命中同文件、`grep -ril` 全文另命中 1 条；`project: 通用` 并集
5. 合并去重：pyc 笔记向量 + grep 双重命中折叠为一条（向量优先置顶），裁 Top 5
6. 输出每行「标题 | summary | 路径 | 命中词」；正文按需精读 ≤1000 字；清单记 DEV_LOG

## 降级路径（证伪）

- **前提**：server 停机或向量零命中（含 min_score 0.4 下无结果）时，检索**自动走 grep 三步兜底链，用户无感知**——不报错、不提示 server 故障、输出协议不变
- **触发判定**：curl `exit≠0`（连接拒绝=7 等）或响应非 JSON / 缺 `memories.normal` / normal 为空 → 完整执行 ② 兜底链
- **已实测**：正常流程向量首条命中 → 模拟 server 不可达（指向未监听端口）→ curl exit 7 → 兜底链照常产出命中清单（实测记录见 T-02 证据）

## 输出协议

- 命中 ≤5 条；0 条时**如实报告「经验库无相关命中」**，不编造、不降级泛谈
- 单次注入精读 ≤1000 字（继承预检护栏）
- 结果必须可解释：每条带命中词（向量命中带 score），agent 能判断为何命中

## 边界

- **只读**：不写、不改、不移动任何笔记（蒸馏/补录走 distill-lesson 与预检守卫）
- 向量检索仅用本地 hy-memory server（`127.0.0.1:19527`，本地模型嵌入），不依赖外部服务；server 不可达时走 grep 兜底而非报错
- 不做自动 hook 注入（触发靠规则，不靠脚本截获报错）
- 不检索 `学习/` 目录（学习笔记非经验笔记；向量命中按 path 剔除）
- 不跨 vault 猜测：未登记项目先走库路由，未登记 → 默认 demo 并提示补登记

## 质量标准

- 结果可解释：每条带命中词与来源路径
- 向量优先：改写措辞查询能命中关键词不重叠的真实笔记（语义召回）
- 纯中文标题笔记可被全文兜底召回（45% 标题无技术词是硬约束）
- 通用经验必在结果候选集中可见（grep 第 ③ 步强制并集）
- 降级可靠：server 停机时兜底链输出与常态同协议
- 空结果如实报告
- 调用留痕（DEV_LOG 召回轨迹）
