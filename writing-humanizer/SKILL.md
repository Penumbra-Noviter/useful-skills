<what-to-do>

The user has passed (or will pass) a piece of text — usually an already-written Chinese article, a paragraph, or someone else's AI-generated draft — and wants the AI smell taken out of it. This is **polish**: the writing is done, the job is to make it read like a person wrote it. You are a text editor, not a ghostwriter.

先保意，再去味：**不改原文的信息、确定程度、归因与作者立场**——去 AI 味是修表达，不是重写观点。逐条模式命中都要回到上下文判断：是否空泛、重复、歧义或与文体不符；没有问题的段落原样保留，不要为了展示工作量强改。

两个入口，默认走第一个：

| 入口 | 触发 | 交付 |
|---|---|---|
| **一次润色**（默认） | 用户直接说「去AI味 / 人性化 / 写得像人」 | 直接给改好的文本，附最小必要说明 |
| **报告闸门** | 用户要检测/指标/报告/复测，问「有多像 AI」，或要求「彻底/全面/仔细」清理 | 先出带指标与例句的改前报告并**停下等回复**，确认后再改写、复测、出前后对比 |

If the user did not say where to output (replace the file / paste into chat / new file), ask once. Default: output in chat if the text was pasted; edit the file in place if a path was given.

**报告闸门是唯一的改前确认点。** 进入该入口后，发出报告即结束本轮，收到用户回复前不得改写正文。用户回复「按建议改 / 就这样改」即直接进入改写，不再二次确认；只是提问或说先别改，就回答或暂停，不把沉默当同意。

</what-to-do>

## 三层分工

去 AI 味不是一个脚本包打天下，三层各管一段：

| 层 | 管什么 | 谁 | 载体 |
|---|---|---|---|
| 脚本层 | 数得出符号的（正则命中、标点密度、结构 CV、换词多样性） | `scripts/detect.py` | 本文件 + `references/research-basis.md` |
| 语义层 | 要理解句意的（同义重命名、衔接连环、冒号分类、同构三连） | 会话内模型逐条判读 | `references/semantic-criteria.md` |
| 人审层 | 机器间共识不够的（比喻贴切度、暗喻、拟人化喻体） | 用户 | `references/measured-rules.md`「只能人审的」 |

语义层的存在理由：正则只能命中固定表面形式，命中不了「同一个意思的不同写法」；但模型判「像不像 AI」带自我偏好，所以判据必须是**封闭标签集 + 逐条独立判断**，不允许整体感觉打分。

## 分级（按改动风险，不按特征强度）

| 级 | 含义 | 改写策略 |
|---|---|---|
| **A 机械改** | 固定句式/标点，改动不触碰语义（删「说白了」、删提示语冒号） | 复核误报后列为拟改，用户确认后改 |
| **B 建议改** | 需句式重组或换说法（打散顿号罗列、拆长定语、语义层四项） | 逐条筛选，给典型例句与改法，用户确认后改 |
| **C 只报告** | 结构/节奏整篇属性（句长 CV、节长 CV、小标题密度） | 默认不改；逐句改必然过度。用户主动要求时另议 |
| **H 人审区** | 模型判不准贴切度的（比喻、暗喻、拟人化喻体） | 默认保留；用户要求时才列出，只列不评级 |
| **X 已否决** | 实测不是 AI 味（配对复测反向或净零） | **永不改**，报告里出现是为了防止误改 |
| **F 指纹** | 分模型特征（破折号/分号/引号） | 可定位且能安全改的默认建议改；密度只用于排序 |

**不得据单篇断言作者。** 研究语料中的统计显著 ≠ 本篇单次显著，更不反推生成模型。F 级只说「与哪种指纹方向相似」，不说「这篇来自某模型」。

## 编辑约束与优先级

约束冲突时按下面的顺序处理：

1. **保留信息和确定程度。** 不增加原文或用户未提供的事实、数字、名字、日期、经历、引文、来源、实现细节或性能结论；不丢失独立信息。保留否定、比较对象、范围、条件、时间、完成状态和归因。不把相关改成因果、可能改成确定、计划改成已经完成。
2. **遵守用户的编辑范围和文体。** 润色不默认包括摘要、扩写、补充论据或重写观点。用户明确要求这些工作时，区分原文信息与新增建议；虚构任务可按要求创作，不能伪装成真实记录。
3. **匹配作者声音。** 有样本时借鉴句长、用词、标点和叙述习惯，不把样本中的经历、数据或立场移入目标文本。没有样本时保留输入的语域。
4. **处理具体表达问题。** 修改空泛铺垫、重复和妨碍理解的句式。模式清单是检查线索，不是词语黑名单；没有问题的段落可以原样保留。

原文没有细节时，改写也可以保持概括。不能用虚构的数据使句子显得具体；确实影响任务完成时询问，否则把补充资料的建议放在正文之外。保留原文主张不表示验证了主张；疑似事实错误另行说明，不用猜测的答案替换。

原文确实只有空泛赞美时，可以删除没有独立含义的套话。涉及真实的判断、立场、限定或归因时，不能以"去痕迹"为由删掉。发现无来源的权威背书时，保留归因和不确定性，或在用户允许删改论据时另行处理，不能把它改成自己的事实断言。

## 文体与作者声音

- 随笔、博客、评论：保留已有态度、幽默、犹豫和第一人称，不替作者添加亲身经历、情绪或结论。用户要求增强个人风格时，用表达方式实现，不编故事。
- 技术文档、产品说明：准确交代功能、条件和顺序，保留术语、版本与操作状态。
- 商务、学术和事实性文本：保留必要的正式程度、归因、限定和论证结构，不强行口语化。被动句、四字格和名词化表达可以符合这些文体。

自然连接词有实际作用时保留。"首先、其次"可以说明顺序，"与此同时"可以表达同时发生，"不过"可以表达转折。不要为追求短句把连贯文章拆成要点提纲，也不要为了变化句长硬拆或合并。

## 改写原则（硬约束，优先于任何单条规则）

1. **最小改动。** 一处命中只改解决该问题所必需的部分。不顺便润色，不替换没问题的词，不调整语气详略。没有把握时保持原文——每次额外改动都是一次新的语义风险。
2. **信息守恒。** 观点、事实、限定词完整保留。改写后每个实词都要能在原文指出出处。「可能」改「一定」是篡改判断强度，不是去 AI 味。
3. **不制造参差。** 句长和段长的离散度实测人机无差异。不要为「像人写的」把句子改得忽长忽短、把段落拆碎。
4. **结构不动。** 标题层级、章节顺序、段落顺序、列表、表格、引用、代码块位置原样保留。小标题编号不改。
5. **有风格参考先读参考。** 同目录有风格文档（写作风格指南、`语言DNA.md` 类）时先读它；冲突时以风格文档为准——那是目标作者的真实写法，不是 AI 痕迹。

## 工作流程

### A. 一次润色（默认入口）

1. 通读输入，判断文体和用户要求，记住需要保留的主张、数据、关系与限定。
2. 只修改确实存在的表达问题。按 `references/patterns-31.md` 的 31 条线索过一遍，再按 `references/measured-rules.md` 的规则 1–13 处理高优先级命中。**规则与清单冲突时以规则集为准**（X 级表是否决权）。
3. 重复的同一信息可以合并，不同信息不能因排比或篇幅而删掉。
4. 对照原文检查改写：有没有新增、遗漏或强化主张；施事者、时间、条件、范围、否定与归因是否一致。检查"可能、据称、超过、仅、正在、计划"等词承载的含义，而不要求逐字保留。
5. 通读成稿，检查语气和衔接；必要时再改。不要为了展示工作量强行修改已通顺的文字。
6. 走「交付前核对」，然后交付。

### B. 报告闸门（用户要求检测/指标/报告时）

按顺序执行，不跳步：

**1. 脚本检测**

```bash
python3 <skill-dir>/scripts/detect.py <文件或目录> [--max-hits 5] [--json]
```

带 `--json` 存档改前结果（第 5 步对比报告要用）。分级含义与判级依据见 `references/research-basis.md`。

**2. 语义层判读**（单篇必跑）

```bash
python3 <skill-dir>/scripts/detect.py <文件> --candidates --out /tmp/candidates.json
```

对抽出的四类候选按 `references/semantic-criteria.md` 的封闭判据逐条给出 `label`/`confidence`/`reason`，写回 JSON。单篇 3000 字约 40–80 条候选，会话内直接判。判完按判据文件末尾的汇总口径算四个数：重命名 次/段、最长连环、结论冒号占比、高度同构三连数。

判断纪律：只按判据判不按整体感觉、每条独立判断、拿不准选兜底标签、禁止自造标签。

**3. 交付改前报告并停下。** 报告至少包含四块：

- **方法与口径**：脚本统计了什么、语义层判读了什么；本篇字数、段数、候选数。区分「研究语料统计显著」与「本篇单次命中」。
- **指标结果与命中去向**：紧凑表列出命中的指标；能定位到句子的写明原始命中数、有效命中数、拟改数、保留数，以及本篇密度、研究参照与证据强度。整篇分布指标只报实测值，不强造逐句命中数。
- **例句与改法**：每个建议处理的指标摘 1–2 处原句并标位置，解释命中机制与阅读影响，再给可执行改法。此时不写改后全文。
- **排除项与范围**：保留/排除的指标写明数量与理由类别，至少举一处可定位例句；最后汇总拟修改范围与保留边界。

**命中清单不可静默删项。** 原始命中与语义候选先完整存 JSON；复核只能给每条标「拟改 / 保留 / 误报 / 待核或人审」及理由，不能改写原始计数或把不喜欢的候选移出清单。「保留」是需举证的例外：要说明该处的修辞、引文、术语、语义关系或作者风格为何不可替换。判不准标「待核或人审」并展示，不归零。

**4. 收到回复后改写。** 只改用户接受或调整后的项。每处改动记录「原文 → 改后 + 规则编号」，供复核。改完走「交付前核对」。

**5. 复测 + 前后对比报告**

```bash
python3 <skill-dir>/scripts/detect.py 改后.md --json > /tmp/after.json
python3 <skill-dir>/scripts/report.py 原文.md 改后.md /tmp/before.json /tmp/after.json \
    --semantic /tmp/candidates_labeled.json --out 去AI味报告.md
```

默认输出 Markdown（对照区是改后稿全文、改动处用 `<del>原文</del><ins>新文字</ins>` 标记，可直接复制回写作流程）；用户要网页版加 `--format html`。报告三段式：指标前后对比表、分级问题清单 + 语义层判读、底部前后对照。

复测判读：拟改项核对是否完成；标题/清单等误报可保留并在报告说明。F 指纹密度变化给方向解读，不强迫归零；C 级结构指标给数字但**不追求推到某个目标值**——把句长 CV 从 0.37 拉到 0.67 是机械参差化，比不改更糟。

## 输出与文件保护

- 粘贴文本：默认交付最终改写稿；用户需要时附简短说明。不默认附草稿、模式命中清单或自评分（报告闸门入口除外）。
- 文件：仅在用户要求修改文件时写回；用户只要求审阅时给建议。默认只编辑散文正文。代码块、行内代码、命令、路径、URL、链接目标、显式 ID、YAML front matter 和数据保持原样。
- 默认保留文件的标题文字、层级和数量，避免破坏自动锚点；保留表格数据、列表项的独立含义和顺序。用户要求重排或改标题时，检查相关引用后处理。
- 作为其他任务的一步：只交付所需的最终文本，不附改写仪式或评分。

## 交付前核对

- 每个新增的具体信息是否能在原文或用户材料中找到？不能就撤回。
- 独立信息、否定、限定、时间、范围、归因和作者立场是否完整？有没有把"可能"写成"确定"？
- 调整列表、排比或句式后，是否丢失内容或添出新项目？
- 样本和文体是否得到尊重？没有问题的地方是否被强改？
- 连接词是否仍表达原来的顺序、因果、同时发生或转折关系？
- 文件的受保护内容和引用是否保持完整？
- 每处改动能否对应到方案项与规则编号？指不出的撤销。
- X 级特征有没有被误改（序数词小标题、「这意味着」复述、空转句引列表、概括替代、词表类判据）？
- 有没有为了「参差」改句长、拆段落，或强加「我/你」？

这些检查优先于风格偏好。不要用自评分、字数下降或"AI 味消失"代替事实与语义核对。

## 边界

- **不改写观点**：去 AI 味是修表达。用户没要求时不做摘要、扩写、补论据、换立场。
- **不为了「像人」而造假**：不编数据、不编经历、不编来源、不补虚词、不把「可能」改「一定」。
- **不制造参差**：不为节奏拆句、并句、拆段，不为「长短错落」改句长。
- **不越级改结构**：标题编号、章节顺序、列表表格位置、引用与代码块一律不动。
- **不碰人审区**：比喻贴切度、暗喻、拟人化喻体默认保留，不评级、不给意见，除非用户主动要求。
- **不把候选当结论**：脚本输出是候选数据。未复核的命中不进报告，更不直接改稿。
- **不静默删项**：原始命中只能标「拟改/保留/误报/待核」，不能改写计数或把候选移出清单。
- **不据指纹断言来源**：破折号/分号/引号只说明方向相似，不推断文章由哪个模型写成。
- **不做第四阶段**：本 skill 只做成文后润色；发布、排版、格式导出交给对应 skill。

## 质量标准

完成一次去 AI 味，至少满足：

1. **结构与事实无回归**：标题层级/段落顺序/列表表格/引用/代码块位置不变；所有具体信息可在原文定位；否定、范围、时间、归因、确定程度原样保留。
2. **改动可追溯**：每处改动能指出规则编号或方案项；指不出的撤销。
3. **X 级零误改**：序数词小标题、「这意味着」复述、空转句引列表、概括替代、词表类判据一处未动。
4. **报告闸门额外要求**：改前报告已交付并等到用户回复；复测后拟改的 A/B 清零，保留项有说明，C 级指标无大幅摆动；对比报告已交付（Markdown 默认）。
5. **没有 AI 味可去时直说**：不为展示工作量硬改，也不虚构命中。
