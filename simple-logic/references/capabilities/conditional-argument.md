# 条件论证评估器

## R — 原文 (Reading)

> "为了保证条件论证的有效性，我们必须彻底理解大前提A→B在告诉我们什么。这是说A和B之间一定要有必然联系。换句话说，如果A实现，则B必然要能实现。"
>
> — D.Q. 麦克伦尼, 第3章 09 条件论证

---

## I — 方法论骨架 (Interpretation)

"如果 A 那么 B"（记作 A→B）的评估分两层。第一层是形态判定：四种推理路径中只有两种有效——肯定前件（A 成立，所以 B 成立）与否定后件（B 不成立，所以 A 不成立）；两种无效——否定前件（A 不成立，所以 B 不成立）错在把 A 当成 B 的唯一条件，A 缺席推不出 B 缺席；肯定后件（B 成立，所以 A 成立）错在 B 可以由多种原因触发，B 成立不锁定 A 是唯一解释。第二层是可靠性评估：严格逻辑意义的条件论证在现实中很少，多数条件句（"如果周四天晴就去露营"）前提与结论之间没有必然联系；此时判断标准转为——联系越紧密（存在机制性因果），结论成立的可能性越大；可靠预测来自对过去事实的积累（"过去 15 年只要叔叔到镇上就去施密特餐馆"），而非单次假设。输出结论时按证据强度给"必然"或"可能"，不把"应该会"说成"一定会"。

## A1 — 书中的应用 (Past Application)

### 案例 1: 路易斯跑步与移动（四种形态全演示）
- **问题**: "如果路易斯在跑步，那么他一定是在移动。路易斯确实是在跑步。所以，路易斯在移动。"——同一条件句换四种推理，作者要演示哪些成立。
- **方法论的使用**: 形态矩阵逐项核对——肯定前件（跑步 → 移动）成立；否定后件（没移动 → 没跑步）成立；否定前件（没跑步 → 没移动）不成立，因为走路、翻身、跳舞机都能让他移动；肯定后件（在移动 → 在跑步）不成立，移动的途径不止跑步。
- **结论**: 有效形式的根基是 A 与 B 之间存在必然联系；无效形式的结论可能碰巧正确，但不必然。
- **结果**: 跑步例成为条件论证形态学的标准模板，正向（第3章 09 节）与负向（第5章 01-02 节）互证同一矩阵。

### 案例 2: 公牛队与季后赛（弱条件论证）
- **问题**: "如果公牛队获胜，他们将进入季后赛。"——前提与结论之间并非必然：公牛队赢了，但可能因球员罢工导致季后赛取消。
- **方法论的使用**: 判定这是弱条件论证后转可靠性评估——检查联系紧密度（胜负与季后赛资格的常规因果机制）与历史积累（过往赛季兑现情况）。
- **结论**: 联系虽非必然但较牢固，结论仍然可靠；可靠性取决于对前提与结论联系程度的了解。
- **结果**: 此例说明"非必然"不等于"不可信"，评估的关键是联系强度而非绝对确定性。

### 案例 3: 中六合彩捐慈善（承诺类条件句）
- **问题**: "如果我中了六合彩，我将把奖金全部捐献给慈善机构。"——朋友的承诺该信几分？
- **方法论的使用**: 先查"如果"前提的成立概率——中奖概率微乎其微；再查承诺兑现路径——即便中奖也未必兑现。两条都是弱联系。
- **结论**: 前提实现概率极低 + 联系脆弱时，就此下结论是草率的。
- **结果**: 此例确立承诺评估的双重检查：前提成不成立得起 + 承诺兑现靠不靠得住（第3章 09 节）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 预测类断言：市场预测、天气预报、业务推演——"如果 X 发生，Y 就会发生"，先判形态再估可靠性。
2. 承诺类语句：口头承诺、合同条款、政治许诺——"如果我/你……就……"，检查前提概率与兑现路径。
3. 技术风险评估："如果该组件故障，系统会宕机吗""如果上线此功能，用户会流失吗"——A→B 的机制联系与历史数据。
4. 归因论断的拆解："他没来开会，所以肯定不关心项目"——否定前件在口语中的日常变形。

### 语言信号 (用户的话里出现这些就应激活)

- "如果…就 / 只要…就 / 只有…才 / 除非 / 必然 / 一定 / 预测 / 承诺 / 风险 / 他肯定会 / 这样下去准会"
- "if…then / only if / whenever / as long as / will definitely / guarantee / prediction / promise / risk assessment"

### 与相邻 skill 的区分

- 与 `fallacy-detector` 的区别: 否定前件、肯定后件是本 skill 形态矩阵中的两项，也是谬误识别器的形式谬误子集；条件 skill 正向评估完整矩阵 + 弱条件概率，谬误识别器只做负向贴标签。
- 与 `argument-evaluator` 的区别: 条件论证是结构检查的一个常见形态；当问题只是"这条件句成不成立、有多可信"用本 skill，当要对整个论证走四步评定（含前提真实、相关）用评定器。
- 与 `root-cause` 的区别: 肯定后件在归因场景（由结果锁原因）会滑向因果链领域；因果链追踪管"原因到底是什么"，本 skill 管"条件句推理是否有效、结论多可信"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **规范化条件句（A→B）**
   - 完成标准: 把句子改写成"如果 A 那么 B"，明确标出前件 A 与后件 B；识别口语里的变体（"只有 A 才 B" = B→A，"除非 A 否则 B" 等）。
   - 判停条件: 无法提取 A 与 B（没有条件结构）→ 本 skill 不适用，转 `argument-evaluator` 做整体评定。

2. **判定四种形态**
   - 完成标准: 还原实际推理路径（肯定了前件 / 否定了后件 / 否定了前件 / 肯定了后件），对照矩阵输出"有效 / 无效"；对无效形态，补出正确推理应该是什么。

3. **弱条件论证可靠性评估（当 A→B 非必然联系时）**
   - 完成标准: 两项检查——①联系紧密度：A 与 B 之间有无机制性因果，还是纯巧合/惯例；②历史积累：过往有多少次 A 发生且 B 兑现的实例。输出结论强度为"很可靠 / 较可靠 / 不可靠"的概率表述，不输出"必然"。

4. **输出评估结论**
   - 完成标准: 有效形态给"必然"级结论；无效形态指出错误形态 + 正确的推理路径；弱条件给"可能 + 依据 + 置信度"；预测类输出明确标注其概率性质。

**输入契约**: 含"如果……就……"类条件结构的断言（预测、承诺、技术风险评估），须能提取出前件 A 与后件 B，并还原实际推理路径。无法提取 A 与 B（没有条件结构）时本能力不适用，转 `argument-evaluator` 做整体评定；弱条件评估还需了解 A 与 B 之间的机制联系及过往兑现实例，信息不足时应先向用户询问补充。

**输出契约**: 形态判定（有效 / 无效，无效形态补出正确推理路径）+ 结论强度。有效形态给"必然"级结论；弱条件给"很可靠 / 较可靠 / 不可靠"的概率表述 + 依据 + 置信度；预测类输出明确标注概率性质，不把"应该会"说成"一定会"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 无条件因果断言：没有"如果"结构的直接归因（"广告带来了增长"）属于因果链追踪领域。
- 已有具体概率数据的决策：手头有真实统计分布时，直接做定量评估，本 skill 的定性"联系紧密度"是降级方案。
- 纯符号逻辑习题：形式逻辑的严格语义（真值表、量词）超出本书范围，本 skill 面向日常论证，不保证覆盖全部逻辑系统。

### 作者在书中警告的失败模式

- 否定前件（ce01）：把"如果 A 就 B"听成"只有 A 才 B"——A 只是 B 的充分条件，不是唯一条件；"他没来开会所以肯定不关心项目"式推断即此。
- 肯定后件（ce02）：B 成立只说明某个充分条件被满足，不锁定具体是哪一个；"他成功了所以方法一定对"忽略运气与时机。
- 弱条件论证草率下结论（ce55）：前提实现概率微乎其微（中六合彩）或联系脆弱（天晴与露营无机制关联）时，把"应该会"说成"一定会"即草率。

### 作者的盲点 / 时代局限

- 必然性理想在不确定性决策中的局限：作者自己承认"严格逻辑学意义上的条件论证真的很少"，但只给出"联系紧密度 + 历史积累"的定性指引，没有系统概率框架（贝叶斯式更新缺失），对"该信多少"的量化能力弱。
- 朴素因果假设：A→B 的机制性假定未经因果推断方法检验——混杂因素、反向因果、反事实都未讨论，"历史积累"可能只是相关而非因果。
- 单一文化例证（NFL、州长竞选），且未涉及当代信息环境下条件句被系统性误用（算法放大、标题党利用"如果不……就会……"制造焦虑）的结构性维度。

### 容易混淆的邻近方法论

- 充分条件 vs 必要条件："如果 A 就 B"（A 充分）与"只有 A 才 B"（A 必要）互换是常见滑移，也是否定前件谬误的机制来源——先标清方向再判形态。
- 条件句为真 vs 用条件句推理：A→B 这个句子本身真假（如"如果下雨地面会湿"）与"用 A→B 做推理"是两回事，前者查内容，后者查形态。
- 历史积累 vs 因果证明：过去的规律性共现（叔叔到镇上→去餐馆）不等于因果证明，本 skill 只据此给"可能"级结论；要证明因果转 root-cause。
